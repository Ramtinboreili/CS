1. The binary tree
@@ a3-1|body#1
A <b>tree</b> is a hierarchical structure of nodes: one <b>root</b>, every node has at most one parent and zero or more children; a node with no children is a <b>leaf</b>. The <b>depth</b> of a node = the number of edges to the root; the <b>height</b> of a tree = the maximum depth. In a <b>binary tree</b> every node has at most two children (left/right). A binary tree of height $h$ has at most $2^{h+1}-1$ nodes; so a "full" tree with $n$ nodes has height $\log_2 n$.

@@ a3-1|body#4

@@ a3-1|body#5
<b>Postorder</b> (left, right, root): suitable for deleting a tree and computing subtree sizes.
@@ a3-1|body#6

2. The binary search tree (BST)
@@ a3-1|body#9
Property: for every node, all keys of the left subtree are <b>smaller</b> and all keys of the right subtree are <b>larger</b> than it. Search and insert compare the key and go left or right, with cost proportional to the <b>height</b>: $O(h)$. Deletion has three cases: a leaf (just remove), one child (replace with the child), two children (replace with the <i>inorder successor</i> = the smallest element of the right subtree, then delete it).
@@ a3-1|body#10
<b>The problem:</b> if keys are inserted in sorted order the BST turns into a linked list of height $n$ and all operations become $O(n)$. For a random BST the expected height is $O(\log n)$ but this cannot be guaranteed for arbitrary input. The solution: <b>self-balancing trees</b>.

4. The red-black tree
@@ a3-1|body#28
A binary search tree with node colouring (red/black) that maintains five properties: (1) every node is red or black; (2) the root is black; (3) the NIL leaves are black; (4) <b>the children of a red node are black</b>; (5) the number of black nodes on every path from the root to a NIL is the same (black-height). Consequence: the longest path is at most twice the shortest and the height is $\le 2\log_2(n+1)$.

Explain heap sort with its steps and complexity. Why is it often slower than quicksort in practice despite being $O(n\log n)$?
@@ a3-2|ex:4:a#0
