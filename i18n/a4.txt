3. The lower bound for comparison sorting
@@ a4-1|body#29
Every comparison-based algorithm can be modelled by a binary <b>decision tree</b> in which each leaf is one of the $n!$ possible permutations. A binary tree with $n!$ leaves has height at least $\log_2(n!)$ and by Stirling's approximation $\log_2(n!)=\Theta(n\log n)$. So no comparison-based algorithm can do better than $\Omega(n\log n)$ in the worst case. Algorithms like <b>counting sort</b> and <b>radix sort</b> escape this bound by using the structure of the keys (integers in a small range): counting sort runs in $O(n+k)$.
@@ a4-1|body#30
<b class="t">In practice</b>Standard libraries usually use hybrid algorithms: Timsort (Python/Java for objects: a combination of merge and insertion sort that detects sorted runs) and Introsort (C++: quicksort that switches to heap sort when the depth gets large). You do not need to write your own sort except for learning.

Why can't we build a "comparison" sorting algorithm with $O(n)$ worst-case comparisons? (decision-tree argument)
@@ a4-1|ex:4:a#0
To identify one of the $n!$ input permutations the algorithm needs at least $n!$ distinct leaves in its decision tree. A binary tree with $L$ leaves has height at least $\log_2 L$, so the worst-case comparisons are $\ge\log_2(n!)$. By Stirling $\ln n!\approx n\ln n-n$ ⇒ $\log_2 n!=\Theta(n\log n)$. The concept
@@ a4-2|body#1
Graph traversal means visiting, in an orderly way, all vertices reachable from a start vertex. To avoid looping forever in cycles we keep a <b>visited</b> set. The difference between BFS and DFS is only the data structure of the "frontier": a <b>queue (FIFO)</b> or a <b>stack (LIFO)</b>.
@@ a4-2|body#2
BFS — breadth-first search
@@ a4-2|body#3
mark when entering the queue
@@ a4-2|body#4
time O(V+E), memory O(V)
@@ a4-2|body#5
BFS sees vertices in order of their distance (number of edges) from the source, so on an <b>unweighted graph</b> it gives the shortest path. Why it is correct: the queue always holds vertices at distance $d$ before those at $d+1$ (an invariant).
@@ a4-2|body#6
DFS — depth-first search
@@ a4-2|body#7
post-order: u is finished
@@ a4-2|body#8
DFS goes as deep as possible and then returns (backtracks). By recording the entry/exit time of each vertex, edge types (tree, back, forward, cross) are classified; a <b>back edge</b> means a cycle. The reverse of DFS post-order on a DAG is a <b>topological order</b>.

Dijkstra — single source, non-negative weights
@@ a4-3|body#3
A <b>greedy algorithm</b>: it always takes the closest unfinalized vertex, finalizes it and relaxes its edges. Why it is correct: with non-negative weights the shortest path to the vertex that currently has the smallest $d$ cannot be shorter than a path through another unfinalized vertex. Bellman–Ford — negative edges and negative-cycle detection
@@ a4-3|body#7
It relaxes all edges $V-1$ times. Since a shortest simple path has at most $V-1$ edges, the distances are final after $V-1$ rounds. If an improvement still occurs in round $V$, a reachable <b>negative cycle</b> exists and the shortest path is undefined (it can be decreased to $-\infty$). Complexity $O(VE)$.
