Recursion
@@ a5-1|body#1
A <b>recursive</b> function reduces a problem to smaller instances of <i>the same problem</i>. Every recursive solution needs two parts: a <b>base case</b> (finishes without a recursive call) and a <b>recursive step</b> that surely moves toward the base case. Otherwise it either runs forever or overflows the stack. Correctness is proved by <b>induction</b>.
@@ a5-1|body#2
x^n by divide and conquer: O(log n)
@@ a5-1|body#3
Each call has a frame on the call stack; the space complexity of a recursion is at least the recursion <i>depth</i>. <b>Tail recursion</b> (the recursive call is the function's last action) turns into a loop in languages with tail-call optimization (Python has none).

Greedy algorithms
@@ a5-2|body#1
A greedy algorithm makes the "best local choice" at each step and never regrets. Its correctness depends on two properties: the <b>greedy-choice property</b> (a locally optimal choice fits inside a globally optimal solution) and <b>optimal substructure</b>. The proof is usually an <i>exchange argument</i>: any optimal solution can be transformed, without getting worse, into one that contains the greedy choice.
@@ a5-2|body#2
<b>Example: activity selection (interval scheduling)</b>: for the maximum number of non-overlapping intervals, sort the intervals by <i>finish</i> time and each time pick the compatible one that finishes earliest. Time $O(n\log n)$. (Sorting by start time or by shortest length is <b>wrong</b>.) Other examples: Huffman, Kruskal/Prim, Dijkstra.
@@ a5-2|body#3
<b class="t">Greedy is not always right</b>For coins $\{1,3,4\}$ and amount 6: greedy gives 4+1+1 (3 coins) but the optimal answer is 3+3 (2 coins). In "canonical" coin systems like $\{1,5,10,25\}$ greedy is optimal.

The minimum spanning tree (MST)
@@ a5-4|body#1
For a connected, weighted, undirected graph, a <b>spanning tree</b> is a subset of edges that connects all vertices without a cycle ($V-1$ edges). An <b>MST</b> is the spanning tree with the least total weight. Uses: network design (cabling/piping at minimum cost), hierarchical clustering. Two key theorems: the <b>cut property</b>: the lightest edge crossing a cut belongs to some MST; and the <b>cycle property</b>: the heaviest edge of any cycle (with distinct weights) belongs to no MST.
@@ a5-4|body#2
Sort the edges ascending; accept each edge if its two endpoints are in different components (it creates no cycle). Cycle detection with <b>union-find</b>. Time: $O(E\log E)$ (sorting dominates).
@@ a5-4|body#3
Kruskal on the sample graph
@@ a5-4|body#4
Starts from one vertex and each time adds the lightest edge that connects the current tree to a new vertex (like Dijkstra with a priority queue): $O(E\log V)$. For dense graphs Prim with a matrix/heap and for sparse graphs Kruskal is usually simpler.
@@ a5-4|body#5
Two operations: <code>find(x)</code> the representative of the set of $x$ and <code>union(x,y)</code> merging two sets. With two optimizations, <b>path compression</b> and <b>union by rank/size</b>, the amortized cost of each operation is $O(\alpha(n))$ where $\alpha$ is the inverse Ackermann function and is below 5 for any practical $n$ — constant in practice.

Topological sort (a reminder)
@@ a5-4|body#8
In a DAG, a linear order of the vertices in which every edge $u\to v$ puts $u$ before $v$. Two methods: DFS (reverse post-order) or <b>Kahn's algorithm</b> (repeatedly remove vertices with in-degree zero using a queue; if not all vertices get removed, a cycle exists). Time $O(V+E)$. Uses: build systems, course scheduling, the execution order of a computation graph (autograd).
